# 需求说明类文档拆分规则

## 文档身份判定（通用原则）

1. 这类文档整体是**一个软件（配置项）的功能规格说明**：
   - software（软件名）= 本文档描述的软件，moduleConfig 字段；
   - subsystem（所属子系统）= 该软件隶属的子系统，moduleSystem 字段。
2. **身份从正文内容判断**，通常写在范围/系统概述/标识/引用叙述中
   （如"本软件是XX系统的XX子系统的组成部分"）。
   **禁止拿章节标题、文档标题或项目名硬填**——它们可能与正式命名不一致。
3. 正文确实没有提及隶属关系时，subsystem/software 返回 null（系统回退初分值），禁止推测编造。

## 功能块校准（通用原则）

4. 功能主体是**功能/能力需求章节的需求树**：树的最细一级功能叙述 = softwareObject（功能块，软件估算对象）。判层级看叙述结构，不看固定章节位置或编号样式。
5. 同一功能块的下级小节（场景/描述/输入输出/元素等细分叙述）给**相同softwareObject**——代码会归并正文，模型不搬运内容。
6. 非功能性章节 drop=true：模板骨架（引用文件、合格性规定、需求可追踪性、注释、术语定义）、纯概述/背景、与软件功能无关的管理性内容。**有功能正文的章节一律归属，不得 drop**（宁可归错再让抽取阶段消化，不丢内容）。
7. 结构异常（层级断裂、伪标题、目录残留、无标题平铺正文）按语义就近归组到功能块；无标题文档的规则初分已按正文线索切块，校准其归属即可。

## 纪律

- softwareObject 用**文档原词**，同块同名；
- **对象收敛**：softwareObject 必须收敛到真正的功能块（一篇需规通常只有几个到二十几个功能块），不要给每个章节各起一个对象名；宁多段同块（代码会归并），不可节节生名；
- **骨架章节必须 drop**：引用文件、合格性规定、需求可追踪性、注释、术语定义、优先顺序等模板骨架章，以及纯概述/背景/约束/环境类陈述章——一律 drop=true，不得为凑覆盖保留或发明归属（抽取调用按段计，保留无功能段纯耗时间）；
- 不确定时保持初分值不变；
- 无标题/纯表格文档：功能块以表格或正文中的功能划分线索为准。
