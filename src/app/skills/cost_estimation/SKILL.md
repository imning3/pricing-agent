# 经费估算功能点识别（ILF/EIF 专属）

## 定位

经费估算服务于**竞标决策阶段**，口径比四号文报价粗：原始功能点 = `35×ILF个数 + 15×EIF个数`。
因此本工具**只识别数据功能（ILF/EIF）**，一切操作功能（EI/EQ/EO）一律不输出。

## 识别规则（继承 fp_pricing 核心规则）

1. **数据实体识别**：完整执行 fp_pricing 的 R-ENHANCE-1~6（模块数据实体、多层级数据、
   库/池/中心、接口数据、智能模型、网络通信六类增强规则）。
2. **穿越判断（R3）**：外部维护只读 → EIF；本系统维护 → ILF。
3. **命名（R8）**：必须是名词（xx信息、xx数据、xx库、xx模型参数）。
4. **去重（R21/R22）**：共用文件只算一次；日志全系统一次。
5. **禁止项（R16/R18/R19/R24）**：抽象机制、缓存临时文件、不可见参数、固化数据一律剔除。
6. **可追溯（R26）**：名称必须在依据文件中有出处。

## 竞标阶段特有判断

- **宁全勿漏**：竞标估算覆盖不全会导致报价偏低，识别从严执行穷举；
  每个功能模块按 R-ENHANCE-1 检查是否遗漏 1-3 个数据实体。
- **不编造**：方案未提及的模块不推测其数据实体（R26 优先级高于穷举）。
- **辅助决策口径**：`fpCount` 为数据实体个数（通常为 1），权重折算（35/15）由公式引擎完成。

## 输出格式

只输出 JSON 数组，fpType 仅允许 `ILF` / `EIF`：
```json
{"requirementName": "目标信息", "fpType": "ILF", "fpCount": 1, "description": "依据3.2节；R3本系统维护"}
```

## 自检清单

1. 输出中是否存在 EI/EQ/EO？→ 立即删除（本工具不支持）
2. 是否一个 EIF 都没有？（R5：除非完全单机独立，否则至少 1 个）
3. 每个模块的数据实体是否找全（R-ENHANCE-1~6）？
4. 全部名称可追溯（R26）？
